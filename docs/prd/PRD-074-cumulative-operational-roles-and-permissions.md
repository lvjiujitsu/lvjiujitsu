# PRD-074: Cumulative operational roles and minimum permissions

## Summary
Separate the person's primary identity, cumulative operational roles, and effective permissions. Today `Person.person_type` is singular; when a student receives `administrative-assistant`, they gain broad management access and stop being modeled as a student by type. The Aline case requires a student who trains and supports the kids class without becoming a full back-office member.

## Demand type
An architectural change to the domain, security, and permissions.

## Current problem
- `Person.person_type` is single and used for identity, enrollment, the portal, and authorization.
- `PortalSessionMiddleware` derives `portal_is_administrative`, `portal_is_instructor`, and `portal_is_student` only from `person_type.code`.
- `PortalRoleRequiredMixin` authorizes through `allowed_codes`, comparing the single type.
- `ADMINISTRATIVE_PERSON_TYPE_CODES` grants complete management; there is no intermediate role for class support.
- Aline (`920.000.011-81`) is seeded as `administrative-assistant`, but she has an enrollment/graduation and supports the kids class.
- Miguel (`920.000.012-62`) is also seeded as back office, but with no training context in the current JSON.

## Goal
Allow a person to have:
- a primary person relationship for registration and billing;
- multiple active operational roles;
- permissions derived from capabilities, not from a single type;
- a class support scope with no financial/full-record access;
- atomic transactions and authorization tests.

## Risks and edge cases
- Broad permission may keep leaking if any view keeps using `person_type` directly.
- A student with class support must not reach finance, stock, or profile management.
- A technical admin with no `portal_person` must keep master access.
- Enrollment and class support must be independent: training does not imply managing; supporting a class does not imply administering.

## Rules and constraints
- The backend is the source of permission; the frontend only reflects it.
- Multiple writes in a transaction.
- Routes and code in English; the interface in Brazilian Portuguese.
- Test-first.
